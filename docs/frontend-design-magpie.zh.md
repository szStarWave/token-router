# Token Router 桌面端设计：以应用为中心

> 状态：评审稿（2026-11-18）。本文定义下一版桌面界面的信息架构、主要页面、交互与验收；不代表功能已实现。
> [原桌面设计](./product-design.zh.md)保留为 D1/D2 的设计基线。本文提议调整入口、跨页任务和发布顺序，沿用原设计的草稿保护、状态反馈与可访问性要求。不改变[管理 API 契约](./contracts/admin-api.zh.md)或[路由内核语义](./archive/rewrite-v2-design.zh.md)。

## 1. 设计决定

Magpie 的[中文快速入门](https://usemagpie.ai/docs/zh/start)以「添加供应商 → 在 Agent 行内选择模型 → 可选地换成路由组」组织产品。Token Router 的供应商、目录、模型入口、接入和账本已有各自的页面，但从 Codex 切换模型，用户仍要先理解候选投影、虚拟模型和接入向导。此前调整了导航和状态反馈，没有消除这些前置步骤。

**把「应用」作为默认工作台，从应用行切换模型或路由组。** 选择器统一展示网关已经暴露的入口；有一个成员的显示为「单成员入口」，不承诺固定派发。先对齐 Magpie 的高频任务：添加与导入供应商、为应用换模型、保存与切换方案、建组、查请求与用量、管理网关接入。首批完成 Codex 从接入到真实请求的验证，后续扩到其他已支持应用和方案。

路由组的创建和选择方式对齐 Magpie，组内执行自己的策略：由现有虚拟模型、候选池、路由模式和策略决定。请求详情读 Token Router 自己的账本，解释实际派发与回退。**不移植 Magpie 的策略语义，也不把它的订阅、协议或插件能力当成更换界面即可获得的功能。**

## 2. 参考范围与差异

资料优先级：官方文档确认任务及术语；固定提交的源码确认界面入口、交互和功能边界；截图只提供当时的布局与密度参考，不足以证明全部状态。详见[附录](#附录来源与证据)。

| Magpie 参考 | Token Router 设计 | 实现边界 |
|---|---|---|
| Agent 行点击模型，选单模型或组 | 应用列表行内选目标，接入和切换复用一个入口 | 已有接入写入；结构化读回与安全改写需补宿主能力 |
| 供应商、账号、模型目录放在一起；支持导入和测试 | 在同一个供应商详情完成账号、模型和配额管理；回到原应用继续 | 已有 API Key、引用、目录与候选投影；不把现有引用导入说成订阅登录态导入 |
| 路由组可像模型一样被选择 | 将现有 `virtual_model` 按成员数和策略显示为单成员入口或路由组 | 保持客户端模型 ID、TOML schema 和路由策略；不引入 `group/` 协议或嵌套组 |
| 保存并切换一套 Agent 设置 | 「应用方案」保存目标选择并预览变更 | 需要宿主保存/应用能力；与内核路由 `profile` 无关 |
| 路由视图 / 用量 / 网关 | 活动查看已完成请求的决策；用量看聚合；网关管理接入和密钥 | 不把后台刷新称作实时路由跟踪；成本和应用归因以实际字段为准 |

## 4. 应用工作台

```text
应用                                                       [扫描本机] [手动接入]
网关：已连接                                    方案：未应用方案 [保存当前…] [切换…]

应用 / 位置          已配置目标                 接入状态                  操作
Codex · Windows     DeepSeek V4 Flash  ▾        配置已验证                查看活动 ›
Claude Code · WSL   工作路由组          ▾        已接入 · 未验证            验证配置
OpenCode · Windows  —                          未接入                    选择模型

需要处理   1 份配置已保存，重启网关后生效                       [查看变更]
```

### 4.1 列表与状态

- 每行对应 `应用类型 × 宿主位置`（Windows 与不同 WSL 发行版各自一行）。默认显示扫描发现的应用；未安装、无法检测和未支持自动接入放到「添加应用 / 手动接入」，不要铺满首屏。桌面不能检测时给出重试；普通浏览器只给手动接入，不显示假扫描结果。
- 「已配置目标」只显示从目标应用读回、且确实指向当前网关的模型；其他网关或直连厂商标「外部配置」。无法读回显示「未知」，目标 ID 无法在当前运行配置中解析时显示「目标不可用」。上次界面选择不能当作读回事实。
- 「已接入」是配置指向本机所选网关；「配置已验证」是计划应用后读回校验成功；「已收到请求」需要关联账本记录。三者分开，不把写入成功当作真实调用已成功。无法归因到本机应用实例时，不显示实例成功标记，只链接按可证的请求维度筛选。

### 4.2 同一个模型选择器

```text
为 Codex 选择模型
[ 搜索模型名称、供应商、组名                            ]
  固定模型   DeepSeek V4 Flash   DeepSeek · 主账号
  路由组     工作               3 个成员 · 级联
  待生效     夜间               重启网关后可选
─────────────────────────────────────────────────────────
  添加供应商…                                      新建路由组…
```

- 默认只允许选择运行中已确认暴露、且适配该应用协议的入口；能力未知不展示为已兼容，明确提示验证条件。不把目录中仅发现的模型、原始候选 ID 或测试专用 `candidate:` 值当成应用可发送的模型。
- 单成员入口仍然经过网关：选一个具体候选，按既有 `single` 模式生成入口；校验并保存 TOML、重启生效后才能配置给应用。`single` 不等于禁用回退，不能据此承诺「只走这个上游」；严格固定派发不在首批范围。首批不自动合并多账号，也不在选择器里绕过路由。
- 已接入应用切换目标时，先读当前配置，再显示「旧目标 → 新目标」及影响范围。只有宿主能证明保留原端点、凭据引用、非目标模型槽位和其他设置时，才提供精简确认；外部配置、首次接入、多个槽位或不明确的变更走完整预览。默认不在点击列表项时写文件。
- 选择器没有可用目标时，「添加供应商」返回原应用及选择上下文。若操作改变了运行配置，等新入口可用再允许继续，不用旧缓存或草稿冒充可选目标。

### 4.3 首次接入 / 切换确认

1. 从应用行选择目标；没网关凭据时，引导按支持方式配置**推理**凭据引用。手动接入展示相应协议的真实地址与模型 ID，示例里的凭据用占位符。
2. Rust 宿主预览会改哪些文件、模型槽位与重载要求。预览不能含已解析凭据或敏感 Header；关键变更如 URL 变化要显示。写入以同一份预览的文件基线为条件，检测到外部改动则停止、重新预览；不要把现有网关 TOML 的 CAS 当作 Agent 文件也已有 CAS。
3. 用户确认后由宿主备份并写入，读回实际目标供列表更新。写入成功但校验失败：显示「已写入，未验证」，给「重试验证」「查看差异」；多文件部分失败按文件报告，不声称全部回滚。提示是否需要开启新会话或重载应用，以对应适配器支持为准。
4. 「查看活动」打开「活动 → 会话」的最近调用。用户第一次从应用发出请求后，呈现真实结果、实际派发和请求 ID；没有可证的应用归因时按入口和时间定位，并标记数据粒度，不猜是哪个 Codex 实例。

### 4.4 应用方案（下一批）

「保存当前」只保存选定应用实例、槽位和目标 ID，在本机宿主内处理；不保存凭据明文、提示词、上游配置或历史文件全文。切换前逐项列出「将修改 / 目标已不可用 / 目标不在本机 / 配置有冲突」，默认不写有冲突项，不能把部分应用标成「全部已切换」。方案改名或删除不改写应用。若当前配置后来由用户手改，显示「与方案不同」，不按最后点过的方案高亮。先完善窗口内切换，托盘快捷操作不阻塞首批。

## 5. 供应商

左侧按「已添加 / 添加供应商」组织。右侧是 Magpie 式单页编辑器：标题显示厂商、状态与端点；分区为「基本信息 / 账号 / 模型 / 端点 / 高级（折叠）」，不再使用页签。账号为紧凑行（掩码指纹 + 使用状态），模型以已选 chips + 待选列表呈现，用途与能力标签收进「模型设置」；账号与模型勾选即时保存，名称与端点在底部「保存」提交。

「模型设置」的字段全部有运行语义：模型名 = 候选 id；上游模型 = 发往上游的 `model`；上下文窗口参与选路过滤（未设置回退供应商模板默认值）；价格进入成本闸与账本；支持图片输入是模态硬过滤；协议模式写候选 `provider`（三种 wire 协议都由上游层实现）；推理档位写 `thinking_levels` 白名单，关闭思考写候选 `disable_thinking`（剥离推理参数 + 已知厂商关闭开关）；最大输出编译为候选 `max_tokens` 上限（请求值更大时截断并记 `OUTPUT_CLAMPED`）；请求头随流式与非流式请求一起发送。embedding / rerank 模型不进入对话模型目录。

供应商类型可改：保存后按新类型重编译，仍是旧类型默认协议的候选一起迁移到新协议，显式改过协议的模型保持不变；类型同时决定目录探测鉴权（Anthropic 用 `x-api-key`，其余用 Bearer）。

| 操作 | 首屏行为与失败出口 |
|---|---|
| 添加供应商 | 可搜索模板，区分厂商 API Key、本地服务、自定义端点。预填可编辑的连接信息；未支持的订阅登录不显示可点击按钮。若模板的免密方式没有经过验证，提供手动指引，不伪造可连通状态。 |
| 导入 | 先做只读扫描，列出来源、端点和是否有可用引用；确认后才创建。明确扫描发生在哪台机器；连接外部服务时不得把服务端扫描叫「扫描本机」。保留原应用配置；账号创建失败时在已创建厂商上重试账号，不重复创建。 |
| 验证账号 / 刷新模型 | 单独显示；刷新目录成功不等于账号可执行请求。失败后保留上次有效目录并标明更新时间；可搜索模型、看已选及停用模型，手动添加时说明来源。 |
| 让模型可供应用选择 | 先选目录模型，再走现有候选投影与配置流水线；只持久化现有 TOML schema。说明现有「应用模型选择」覆盖所有供应商；有草稿或冲突时给明确出路，不能静默改掉同名路由组或用户编辑。写盘后仍显示「待生效」。 |
| 配额与高级 | 账号和模型行只显示有证据的配额。区分「估算 / 未知 / 已耗尽」，不把候选窗口加成账号余额。余额页只展示厂商 usage 接口返回的余额/计划/订阅窗口（OpenCode Go 的 rolling/weekly/monthly），无公开接口的厂商明确「未提供余额接口」。代理、静态非敏感 Header、端点覆盖在高级区。停用账号时说明重新应用模型选择及重启前，运行中的路由可能仍使用它。 |

目标流程允许用户从单个模型行点「供应用使用」：页面替用户组织已有步骤，但仍需预览配置影响、完成校验与重启。若要只更新一家厂商或只发布一个模型，需要确认增量投影契约；首批没有该能力时只呈现全量操作的真实范围。

## 6. 路由组

```text
[筛选路由组和模型…]        6 个组 · 6 个启用              [+ 新建组]
┌ DeepSeek V4.1 Flash  默认入口  auto-deepseek…  ●  ˅
│  [deepseek-v4-flash] [deepseek-v4-flash ×3]  模式 级联  判断 LLM  2 条规则
│  名称 / 组 ID                 Agent 里选 deepseek-v4-flash
│  模型                      [+ 添加模型]
│   ● DeepSeek V4.1 Flash   硅基流动 · 主账号 …1c72
│   ● ...                   手写候选 ⚠
│  账号（只读推导）  硅基流动  全部 2 个启用账号   [任一账号]
│  规则                      [+ 添加规则]
│  路由判断                  [不使用 / 启用判断]  [判断模型]
│  高级 ▾   模式（共享 profile，只读）/ 策略（只读）/ 上下文窗口 / 模型列表 / 推理档位（关闭思考·成员共有·自定）/ 默认入口 / 测试 / 删除
└
┌ GLM-5.3-Flash  ●  ˅        （收起行：名称、ID、成员 chips、模式、判断、规则数、启用）
```

- 单列手风琴：一次展开一个组；收起行保留名称、ID、成员 chips、模式、判断方式、规则数、启用开关。组 ID 是客户端模型名，已生效后不建议原地改。
- 建组只需稳定 ID（名称可留空沿用 ID）；名称可改。无法完整查出外部引用时，删除或改 ID 要说明可能导致外部客户端失效，不能给出「无人使用」的结论；优先引导新建并切换应用。
- 成员按供应商与模型展示：候选 id 形如 `<provider>-<model>-<account8>`，界面反解 provider 前缀并显示供应商名；账号来自候选 id 末尾的 account8，映射到供应商页的账号标签与指纹；匹配不到供应商的写成「手写候选」并提示替换。成员可移除；「添加模型」用按供应商分组的选择器，只列已编译的对话候选（判断用途不进入），没有可加入项时引导去供应商页勾选并「应用模型选择」。**不提供上移/下移**：内核按 profile 的 tier 顺序与候选 strength 排序，成员视觉顺序不参与路由；「本次尝试顺序」在请求详情按实际 attempts 展示。
- 账号区只读：列出成员候选覆盖的供应商与账号；某模型覆盖该供应商全部启用账号时显示「任一账号」，否则列出具体账号。组级账号白名单没有配置字段，账号的新增/停用/换 Key 仍在供应商页。
- 判断模型直接从已编译的启用候选里选（选项显示模型名 + 供应商，值为候选 id），不再要求先在供应商页预设「判断」用途；选中即写入组的 judge 服务（endpoint / model / credential / service_id），普通候选写 `llm`，带「决策模型（SystemOne）」标记的候选写 `jev` 并把 endpoint 归一化为 `/v1/systemone`。判断模型不必是本组成员。供应商页把模型用途改成决策模型后，组里仍留着旧的对话 API 配置时，组编辑器提示并提供「改用 SystemOne」。
- 模式来自共享 `profile`（`single` / `cascade` / `verify_after`），高级区只读展示并标注影响的其他组；级别或判官行为须满足现行内核契约，不承诺一定升级、满意或更便宜。策略清单同样只读；策略参数不在界面编辑。Magpie 的 `smart`、`rotate`、`pace`、意图规则不映射为同名按钮。
- 高级区只提供真实生效的字段：只读模式/策略、`context_window`（路由信号提示）、模型列表（`list_members`）、推理档位、默认入口、测试、删除。推理档位分三档：**关闭思考**写 `disable_thinking = true`（决策档位固定 `off`，剥离推理参数，并对硅基流动 / DashScope 发 `enable_thinking: false`、智谱 / Z.ai 发 `thinking.type = disabled`、OpenRouter 发 `reasoning.enabled = false`；未知厂商只剥离参数）；**成员共有**留空跟随成员候选声明；**自定**把勾选档位写进组配置。Magpie 的组级「被限流时 / 迟迟不出字 / 成员全都忙 / 会话保持 / 压缩阈值 / 脱敏 / 只列出本组」在 Token Router 没有对应运行语义，不渲染假开关。
- 复用共享草稿、校验及 CAS。生效后在应用模型选择器出现。组内「测试」默认以组为目标；从成员行测试走物理候选，明确两种路径不同。
- 没有独立候选页：候选只存在于供应商页的模型列表与编译结果里；组内「添加模型」只列能反解出供应商前缀的启用候选，不提供手写候选入口。

### 6.1 实现状态与组级快照降级（2026-11-20，布局更新 2026-11-22）

正式实现保留组列表/单组编辑器、成员、组级 LLM 判断与规则，以及 `enabled` 启停位；2026-11-22 起改为单列手风琴：收起行概览、展开行内配置，不再使用左侧固定列表 + 右侧多卡片的双栏布局。**原型的「保存待启用 / 已启用 vN / 模拟启用」不做单组快照与热切换**：配置仍是全局草稿 → 校验 → 原子 apply → 重启，组停用只是配置中的 `enabled = false`，随同一份全局配置生效。界面因此显示「启用开关 / 已停用」和全局草稿状态，不显示单组版本号。

这是有意降级：现有运行时持有启动时的静态 `Catalog`，没有按组热替换或版本回滚接口；伪造单组「已启用 vN」会让操作状态与真实客户端行为不一致。需要单组灰度或版本回滚时，应另行设计运行时配置热加载与组级版本存储，不在当前实现范围内。

## 7. 活动、用量、网关与测试

### 7.1 活动：这个请求走了哪里

「路由」子页只做路由视图：路由图（入口 → 组 → 候选）、指标条、最近一次请求的路由叙事、上下文窗口与账号配额；**不再重复摆请求列表**——请求级明细统一在「会话」里看，避免两份列表同一事实写两遍。最近一次请求的叙事先看「请求了 `work` → 由 X 派发 → 成功 / 失败」，再看选择依据、计划、实际尝试和判官（仅有数据时）。计划不能显示成已执行，策略贡献不能显示成唯一因果；看到成功尝试才写「已回退并成功」。无译名的原因码保留原值；账本快照不描述为实时追踪，配置指纹不描述为可取回历史配置。

「会话」子页按 `session_key` 展示服务端聚合的完整调用记录（请求数/失败数/决策模型调用与失败/成本/涉及模型），**左右分栏铺满可用宽度**（全屏不居中留白；窄窗口退化为纵向）：左侧列表独立滚动，右侧详情固定可见。点开一个会话把该会话的每一轮请求与每次决策模型调用按时间倒序合并成一张表；点「请求」行看该轮路由与消息，点「决策」行看这次决策模型调用发送的任务、prompt、选项与答案。这是「所有模型调用」的唯一完整入口。

### 7.2 用量：花了多少、花在哪里

沿用现有时间窗与五维聚合（授权身份、模型入口、候选、账号、会话）；先呈现请求、输入/输出、缓存、已计价成本，再按维度拆分。`by=agent` 按授权身份分组，并非按 Codex、Claude Code 或 WSL 安装实例分组，界面用「授权身份」标注；无法区分缺价和零元时，显示「已计价金额，覆盖未知」。图表标注时区、范围和口径；没有真实的上下文成分数据或用量导出能力时，不做可点击空页。

### 7.3 网关：连接和管理

顶部集中显示当前连接地址、协议示例、管理模式和运行状态，下方是网关密钥与诊断。使用 supervisor 的实际已连接地址（保留 scheme 与实际端口）或经过确认的服务地址，不把默认端口当运行状态。「上游账号凭据」「推理网关凭据」「管理凭据」分别命名且不跨用。`external` 缺失或为真以及浏览器模式都不显示本机启停；服务管理员负责外部重启。网关密钥操作沿用已有安全契约，不新增向 WebView 回传或持久化任何管理凭据的路径。

### 7.4 模型测试：随目标打开

从目录行或请求详情打开时，预选一个仍在运行配置中的目标；无效目标如实标示，不自动换成另一收费模型。默认一个，可显式添加到四个；各列独立完成，停止等待不承诺取消上游，真实费用和账本路径在运行前说明。`virtual:` 走路由并记决策账本；`candidate:` 绕过路由，不写路由决策账本，两者都可能产生上游费用。首事件延迟不等于首个可见文本延迟，输出速度以总耗时作分母，不作质量排名；首期不加逐 token 流式、真实取消或估算费用对比。

## 8. 跨页状态、视觉与实现边界

| 状态 / 规则 | 设计处理 |
|---|---|
| 草稿、磁盘和运行 | 草稿通过校验才能提交；If-Match 用打开时磁盘 revision，不用校验返回值。磁盘已保存不等于运行配置已更新；等待新鲜 status 与磁盘 revision 双确认再清全局提示。共享草稿切页保留，当前不承诺关闭可恢复。 |
| 冲突、断连和失败 | 配置 409 保留草稿、查看我的修改或确认载入最新，不强制覆盖。独立的 Agent 文件冲突重新预览。断连/更新中保留可读旧数据并标时间；不将查询失败转成无模型、0 用量或健康。按钮区分权限不足、未启用和请求在途。 |
| 原生与浏览器 | 操作本机文件由 Rust 宿主负责，网关数据走管理代理；不能为浏览器模式伪造本机接入。密钥只存引用（`env:`/`file:`/`keyring:`），admin token 不进 WebView；新建/轮换继承仓库安全约束。 |
| 界面密度 | 保留 OpenChamber / UnoCSS、Vercel 默认亮色与暗色、Inter / Geist Mono、Lucide React 和单套窗口控制。参考应用截图摆放导航、紧凑模型行及详情抽屉；不用 Magpie 的品牌、图标、截图或前端资产。窄窗口改为单栏列表，返回时保留上下文。 |
| 键盘与文案 | 模型选择器支持搜索、方向键与 Enter，Esc 关闭并还原焦点；确认对话框有焦点管理，列表行有可聚焦的真实按钮。状态不能只用颜色；亮暗主题核验对比度，支持减少动态效果。技术标识在详情中可复制。 |
| 界面文字纪律 | 页头只放标题，不写副标题或标语；卡片不写解释性段落。说明只能出现在三处：控件标签、空状态的下一步动作、真实警告/错误。靠文字才看得懂的地方改布局——字段名、表头、状态胶囊、分组、把当前值放进控件本身；口径类说明收进 `title` 悬停提示。同一个事实只写一次，不在每张卡上重复。 |
| 托盘与窗口关闭 | 常驻系统托盘（启动即建）：左键恢复/聚焦主窗口；右键菜单「显示主窗口 / 服务状态（只读快照）/ 退出」。默认「关闭到托盘」：窗口关闭 = 隐藏，网关继续运行；托盘「退出」置真退出标记后走窗口 close，退出守卫（设置页「退出前询问」）仍会拦截确认。两个偏好都在设置页网关组，关闭到托盘开启时草稿守卫不再弹确认（关窗不丢草稿）。 |

**现有接口可复用**：`api/client.ts` / `queries/admin.ts` 的 status、config、provider/catalog、requests、usage、playground；`useConfigDraft` 与全局草稿；Tauri `onboardDetect / Plan / Apply / Verify` 的适配器和 WSL 入口。保留 TanStack Router Hash history、TanStack Query 缓存和 Zustand 的状态职责，不复制第二套草稿或全局 query cache。

**需支持，不能靠 UI 模拟**：

| 缺口 | 首期实现或保守退路 |
|---|---|
| 本机应用已配置目标读回 | 扩展 Rust 宿主适配器，返回脱敏的实例、端点判定、模型槽位和模型 ID；旧宿主显示「未知」并保留引导。`DetectReport` 的 `already_configured` 不是模型读回证据。 |
| 安全、精确的模型切换 | 宿主明确区分初次接入和最小变更；将预览与实际写入绑定，校验原文件状态。未支持的应用继续走可审查的接入向导。 |
| 可信可选目标 | 需核对可用的运行时模型来源。首期可以在新鲜磁盘 revision 与运行 digest 一致时由磁盘入口生成清单；两者不一致或请求失败就禁用未确认目标。若要继续选择旧的运行目标，走受支持的运行时目录，不从草稿猜。 |
| 应用归因 / 方案 | 先依据现有可证字段显示请求和用量；精确到宿主/WSL 实例、保存应用方案及分项执行需要明确的数据或宿主契约。 |
| 订阅接入、实时路由、历史配置、完整计价覆盖 | 独立评估。不是首批前端能力，不用假控件、模拟数字或不受支持的授权方式顶替。 |

内核冻结：`v2/crates/{core,decide,proto}` diff = 0；新增候选/虚拟模型只改 TOML；管理 API 的 DTO 改动走 `contract-check` 更新绑定。文档不重新定义路由、协议与鉴权；需要新策略时继续走 SignalBag extractor / Strategy 扩展点。

## 9. 交付与验收

| 批次 | 交付 | 验收场景 |
|---|---|---|
| **F1 应用工作台 + Codex** | 应用设为默认；供应商添加/导入回流；同一个选择器；已有及新建单成员入口与路由组；Codex 读回、预览、确认、验证；从应用跳请求 | 从隔离空配置添加或导入供应商，选择模型并让 Codex 发真实网关请求，核对实际派发与请求 ID；再在应用行内切路由组并核对决策证据。注入 409、重启失败、预览后外部改配置、断连、读回失败：不得丢草稿、静默改文件或误报成功。 |
| **F2 日常管理** | 扩到已支持且通过读回/最小写入测试的适配器；完整组编辑；供应商/网关细节；活动与用量跨页筛选；应用方案 | 原生宿主和 WSL 分列；两个应用切换方案时只修改确认过的槽位；某应用失败，其他应用和整体分别展示结果。用量跳转的筛选与实际账本一致；旧地址可达。 |
| **F3 评估补齐** | 逐项决定托盘快捷切换、实时路由视图、订阅连接、上下文构成、费用覆盖等 | 每项要有独立权限、数据来源和契约验收；不阻塞 F1/F2。 |

F1 验收分两层：浏览器夹具跑导航、状态和失败路径；原生隔离宿主用临时应用配置及受控上游验证真实文件、读回和请求账本。模拟结果不能代替原生通过记录，不使用日常用户的配置和凭据。最小手工验收记录：从零配置到首次记录是否需要手改 TOML、每个确认前后状态是否准确、已接入切换是否只从应用行发起、有无意外文件改动、缺数据是否明确显示。构建门禁沿用前端 `lint`、`test`、`check:uno`、`build` 与适用的 Rust 门禁；GUI 补验键盘、亮暗主题、浏览器及外部服务模式。
