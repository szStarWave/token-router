> 状态：**草案（2026-11-18）**。本文是桌面端前端的**产品/交互设计目标态规格**，不是现状描述。
> 约定：凡描述当前行为标注【现状】（证据集中在[附录 A](#附录-a现状代码证据)）；
> 凡新设计标注【目标】；依赖当前不存在的能力一律标注 **需支持**，绝不写成现有能力。
> 事实基准：`v2/apps/desktop/frontend/src/`、[桌面端页面指南](./guide/desktop.zh.md)、
> [前端设计系统](./dev/frontend-design-system.zh.md)、[路线图](./roadmap.zh.md)、
> [管理 API 契约](./contracts/admin-api.zh.md)。
> 本文只管桌面端 WebView 前端的产品与交互设计；路由语义、内核行为、API 契约不在此重新定义。

## 1. 背景与问题

上轮评审结论：前端功能不缺（13 个页面、validate→apply 配置闭环完整），但**按实现模块组织**，用户感知"简陋 + 技术感重"。核心矛盾：每次模型选择的**决策证据**——决策快照、成本分账、策略贡献——已在数据层留存，界面层却不可感知：用户看不到"为什么是这个模型"，也拿不到核查选择质量的材料。质量结论只能由评测给出；界面负责把决策证据呈现清楚，**不做"选得对"式的绝对质量判断**。具体问题清单与代码证据见[附录 A](#附录-a现状代码证据)，摘要：

- 导航 13 项按实现平铺，无任务组织；术语直接暴露 tier/strength/micros/plan_id 等实现概念。
- Models/VirtualModels 草稿是页面内存态，切页即丢；CAS 冲突只弹一串错误文本。
- Providers 五个功能区单页堆叠，模型目录无搜索；账号启用在 UI 上只读。
- 空态只有文字提示无链接；Playground 全部完成后统一渲染、不可取消；请求详情的策略贡献/判官是裸 JSON。

本文的任务：给出以任务组织、术语说人话、细节下沉二级视图、反馈诚实完整的完整规格。

## 2. 设计目标与非目标

### 2.1 目标（按优先级）

1. **以任务组织，不以模块组织**：导航收敛为少数任务入口（首页 / 模型来源 / 模型与路由 / 应用接入 / 请求活动 / 模型测试），技术路由保留但不在主导航平铺。
2. **结论优先、证据可溯**：页面先给"发生了什么/要不要管"的结论，结论可展开追溯到生成它的账本字段；**不编造任何质量评语、成本节省、账户余额、接力成功的说法**。
3. **不丢用户输入**：配置草稿切页不丢、未保存有提示、并发冲突有出路（不静默覆盖）。
4. **等待可感知、退出诚实**：Playground 与长操作有进行中反馈；"取消"如实区分"停止等待"与"上游停止执行"。
5. **术语用户词优先**：模型入口 / 模型来源 / 网关密钥等用户词上界面，技术术语保留为次要标注。
6. **专业细节保留在二级视图**：技术详情层永不删除，可信度不打折。

### 2.2 非目标

- 需要新能力可直接扩展管理 API（破坏性变更记入契约变更记录），并显式标注需支持。
- 不改路由内核语义与配置 schema；界面数字必须来自账本 / status / 配额端点。
- 不做移动端适配（桌面壳，最小宽 1080px）。
- **不做跨设备同步**：草稿暂存是本机行为，不引入云同步/多机一致性（维持路线图非目标）。

### 2.3 设计原则

前三条承接[设计系统](./dev/frontend-design-system.zh.md)，后三条是本文新增的产品层原则：

| 原则 | 含义 |
|---|---|
| 安静优先 | 没有需要行动的事，页面就是安静的 |
| 控件立起、布局平躺 | 卡片无边框靠色阶；可点控件才有 hairline + 短阴影 |
| 颜色只表示状态 | 状态色不做装饰（蓝=进行中，红=错，黄=要注意，绿=正常）；**primary 蓝=动作按钮，selection 中性色=当前项** |
| **结论先于数据** | 每个区块顶部是一句话结论或一个数字，明细在下，原始字段在"技术详情"折叠层 |
| **每个数字有出处** | 结论可点击展开到生成它的原始数据；没有数据的维度显示"暂无数据"，不用 0 充数 |
| **诚实优于好看** | 估算标"估算"、跳过标"未验证"、停止等待不冒充"已取消上游" |

## 3. 用户与使用情境

不假设用户比例，按三类使用情境设计，同一用户可能先后处于全部三种：

| 情境 | 用户在做什么 | 设计含义 |
|---|---|---|
| **首次接上** | 装好后要尽快让 agent 跑起来 | 首页起步清单按真实完成度推进（J1）；术语用用户词 |
| **日常旁观** | 瞄一眼"正常吗/花了多少/有没有要处理的" | 首页状态分型（§6）；结论卡 + 行动横幅 |
| **定位与调优** | 某次请求不对劲、想对比模型、想改路由 | 请求解释（§9.2）、Playground（§9.1）、高级二级视图保留全部专业字段 |

## 4. 信息架构与导航

### 4.1 用户词汇表（导航与页面标题口径）

| 用户词 | 对应实现概念 | 说明 |
|---|---|---|
| **模型入口** | VirtualModel（虚拟模型） | agent 配置里填的那个模型 id；用户视角"我的 agent 用哪个模型" |
| **模型来源** | Provider + Account（厂商与账号） | key 从哪来、哪些模型可用 |
| **模型测试** | Playground | 保留英文名作次要标注 |
| **网关密钥** | Gateway Token / key | 管理面与数据面的访问凭证 + 限额；不再叫"Token"页 |
| 候选 / 策略 / 档位（tier） | candidate / strategy / tier | 进阶视图可达，不进一级导航命名 |

### 4.2 【目标】导航结构

主导航收敛为 **7 个一级项 + 底部系统区**，全部 13 个现有路由保留（可直达，不在主导航平铺）：

```
┌────────────────────────────────┐
│  Token Router            ●就绪 │  ← 侧栏头部：品牌 + 网关状态点
├────────────────────────────────┤
│  ▍首页                /overview│
│                                │
│  模型来源            /providers│  ← 厂商 + 账号；「配额」为其二级标签页
│  模型与路由      /virtual-models│  ← 路由组：每组回答模型 + 判断 + 规则
│  应用接入           /onboarding│
│                                │
│  请求活动            /requests │  ← 请求账本 + 路由解释；「日志」为其二级标签页
│  模型测试          /playground │
│  用量分析              /stats  │
├────────────────────────────────┤  ← 分隔线：以下为低频系统区
│  网关密钥              /tokens │
│  诊断          /diagnostics   │
│  设置              /settings  │
└────────────────────────────────┘
```

路由合并规则（均为前端呈现层合并，旧 path 不失效）：

| 主导航项 | 吸收的旧路由 | 二级形态 |
|---|---|---|
| 模型来源 | `/quotas` | 标签页「余额」（`/quotas` 直达账户余额/订阅；候选限流窗口仍由路由侧维护） |
| 模型与路由 | `/models` | 已删除（候选只由供应商页编译）；旧链接重定向到 `/virtual-models` |
| 请求活动 | `/logs` | 标签页「日志」（`/logs` 直达该标签） |

徽标（只报"需要行动"，不报信息性状态）：模型来源（有待验证账号/目录失败/配额耗尽）、请求活动（无）、诊断（熔断打开，【现状】已有）。

### 4.3 页面职责一句话

| 页面 | 用户问题 | 一级视图 | 专业细节去向 |
|---|---|---|---|
| 首页 | 现在正常吗 | 状态分型渲染（§6）：行动项 / 结论卡 / 起步清单 | 全部链接到对应页 |
| 模型来源 | key 从哪来、能不能用 | 厂商列表 + 选中厂商详情（账号/目录标签页） | 账号表格、header、代理、目录全表、配额窗口明细 |
| 模型与路由 | agent 看到的模型怎么路由 | 路由组卡片：成员模型 + profile + 判断 + 规则 | 展开后的成员候选 id、账号推导、上下文窗口 |
| 应用接入 | 怎么把 agent 指到网关 | agent 卡片 + detect→plan→apply→verify 向导（【现状】保留，费用确认步骤需支持） | diff 全文、配置文件路径、手动接入说明 |
| 请求活动 | 这次请求发生了什么 | 列表 + 结论卡 + 时间线 | attempts 全表、贡献 JSON、reason_codes（§9.2） |
| 模型测试 | 哪个模型更合适 | 一个入口起步的对比列（§9.1） | 原始响应、计时明细 |
| 用量分析 | 花了多少、趋势如何 | 汇总 + 序列 + 热力图 + 五维分解（【现状】保留） | 合计行、缓存命中分解 |
| 网关密钥 | 谁能访问、限额多少 | 密钥列表 + 限额编辑器（【现状】保留，改名） | scope 明细 |
| 诊断 | 服务自检 | doctor + 熔断 + 配置审计/回滚（【现状】保留） | 审计明细 |
| 设置 | 服务与外观 | supervisor 启停/重启（仅 Tauri 桌面模式）、监听、主题、退出前询问、关闭到托盘（【现状】保留） | 只读技术字段 |

## 5. 核心旅程

### J1 开箱旅程（目标 5 分钟）

【目标】零配置或部分配置时，首页渲染**起步清单**。清单的完成判定是"有一个可用的模型入口"，不是中间产物：

```
起步清单
┌──────────────────────────────────────────────────────────────┐
│ ① 添加模型来源（厂商 + Key）                    → 去模型来源页 │
│    验证连通性可跳过；跳过后账号显示「未验证」而非「就绪」，        │
│    本步在验证通过前不算完成（下一步建议：验证账号）。             │
│ ② 从目录勾选模型并应用模型选择（编译候选）      （①或已有候选）  │
│    已有手写候选或可用入口时可跳过，标「已跳过」不算完成。        │
│ ③ 创建可用的模型入口（绑定非空候选池）           （②后可用）    │
│    ← 清单完成的判定线：没有可用的模型入口，前面步骤不算完成。     │
│ ④ 把 agent 指到网关                            → 去接入向导   │
│    接入验证可跳过；跳过后该 agent 标记「未验证」。               │
│                                                              │
│  已完成 2/4 · 下一步：创建模型入口                              │
└──────────────────────────────────────────────────────────────┘
```

判定规则（全部从真实数据推导）：

- ① **三态**，避免"有账号即完成"与"跳过验证 ≠ 成功"互相矛盾：
  - **未配置**（无 provider，或 provider 下无账号）→ 未完成；
  - **已配置，未验证**（有账号，最近一次 verify 非 ok 或被跳过）→ **不算完成**，显示「已配置，未验证」，下一步建议为「验证账号 / 刷新目录」；
  - **已验证**（verify ok）→ 完成。
  - 若实现选择"配置存在即计完成"的口径，必须同步把该步显示为「完成（未验证）」、文案明确 **完成 ≠ 已验证**，且清单的下一步建议仍是验证/刷新。
- **状态纪律**：厂商卡片状态点与「就绪」徽标只认验证结果（账号 verify ok / 目录 ready）——未验证账号不得让来源呈现为 ready。
- ② 完成 = 存在**可验证的产物**：配置中已有被勾选的目录模型（待编译），或已存在非空 candidates（已编译）。已有手写候选或可用模型入口的用户（如本地 Ollama、已有配置迁移）**允许跳过来源步骤**——清单直接从其未完成项继续，不强制走"加厂商→贴 key"；本地无 key（免费端点/本地模型）的用户同样跳过账号要求。跳过的步骤标"已跳过"，不算完成。
- ③ 完成 = 存在至少一个模型入口（虚拟模型）候选池非空，且默认模型可解析到候选。
- ④ 完成 = 最近一次该 agent 的 onboarding verify 为 ok；**跳过 ≠ 成功**，清单保持"未验证"态并在下一步提示。**验证通过只是配置读回校验，不保证后续真实请求一定成功**（上游可用性随时变化）；verify ok 与请求成功是两个事实，**agent verify 不能冒称"真实 agent 已运行"**——"跑通"的判定引导用户去请求活动页看真实请求记录，文案不得混同。
- **部分配置的用户看到的是继续点**：清单按当前数据标出已完成项与下一步，而不是从头再来；已有一家来源时①显示"已有 1 个来源，添加另一家 →"。
- 全程标注"不需要手写配置文件"。

**验收**：全新安装不看文档顺清单走完四步，agent 发出请求且请求活动可见记录；任一步失败时错误含下一步动作链接；只做了①②的用户重开首页看到"从第③步继续"。

### J2 添加模型来源（见 §7.2 布局）

模板选厂商 → 贴 key（唯一必填）→ 一键验证（可跳过）→ 刷新目录 → 勾选模型 → 应用模型选择（编译候选）。每步在厂商详情头部有步骤指示；验证失败给出具体错误与常见原因。

### J3 请求解释（决策证据可溯的时刻，见 §9.2）

点开一条请求，第一屏是一句话结论 + 可展开的时间线；每个结论可溯源到账本原始字段；**没有数据的维度不写因果故事**。

### J4 模型测试对比（见 §9.1）

默认从当前模型入口单目标起步，明确操作添加对比目标（≤4）；运行后逐列独立完成；对比结论只在数据足够时给出。

### J5 配置变更（validate→apply→重启生效）

保留【现状】闭环，补：统一应用栏与未保存提示（§8.4）、CAS 冲突出路（§8.5）、应用并重启（§8.6，仅 Tauri 桌面模式）。改模型入口候选池时提示影响面："影响 agent 看到的 `smart`"。

## 6. 首页关键状态设计

【目标】首页按七种状态渲染，判定全部来自真实查询，**缺数据 ≠ 0**：

| 状态 | 判定 | 渲染 |
|---|---|---|
| A 零配置 | 无 provider 且无候选且无模型入口 | 起步清单（J1） |
| B 部分配置 | 有来源或候选但无可用模型入口 | 起步清单（从已完成项继续，标"下一步"） |
| C 有配置无请求 | 配置齐但账本为空 | 清单收起为"接入 agent"提醒 + 仪表盘骨架（各卡显示"暂无数据"，不是 0） |
| D 正常 | 有请求、无行动项 | 结论卡 + 最近请求摘要 |
| E 降级 | 有行动项（配额耗尽/目录失败/熔断打开/失败率异常） | 行动横幅置顶 + 仪表盘 |
| F 不可达 | status 查询失败或 supervisor 未 ready | 断连横幅（黄），**已加载的旧数据标记"数据截至 HH:mm"，状态点不显示绿色** |
| G 更新中 | supervisor state = starting/restarting | 蓝色"网关启动中/重启中"横幅 + 骨架；完成后自动刷新 |

状态 D/E 的结论卡：

```
┌─────────────┬─────────────┬──────────────────┬─────────────┐
│ 最近24小时   │ 成功率       │ 已计价成本*       │ 模型入口健康  │
│    128      │   99.2%     │  $0.84           │ 熔断 0 打开  │
│ （不写"较昨  │ 1 次上游错误 │ 覆盖需支持*       │ 聚合需支持** │
│  日"对比）   │              │                  │              │
└─────────────┴─────────────┴──────────────────┴─────────────┘
  * 首期口径统一为「最近 24 小时」（与用量分析页窗口一致）。
    成本卡首期只展示已计价金额（账本中已有分账的请求合计）；
    未计价请求的覆盖率 **需支持**（需 DTO 暴露计价覆盖口径）——
    D2 落地前显示"覆盖未知"，不折算、不外推、不宣称覆盖比例。
    没有任何候选配价格时整卡显示"未配置价格，无法估算成本
    → 如何配置"（链接到候选高级标签页）。
  ** "模型入口可用数"不能拿熔断计数直接充数（熔断是候选/上游
    健康信号，不是入口可用性）；入口粒度的可用性 **需支持聚合**
    （入口 → 候选池 → 各候选健康/配额的推导），落地前健康卡
    只显示有据可查的信号（熔断打开数、候选健康表摘要），
    不显示伪造的 "5/7 可用"。
```

- 口径全局一致：首页、用量分析、请求列表统一"最近 24 小时"；页脚注明。无昨日/前期数据时**不显示对比**，不留"—"占位框。
- 成本数字来自账本真实分账；没有数据的维度显示"暂无数据"，不用 0 充数。
- 配额/接力类横幅措辞诚实（§10.2）："N 个候选配额耗尽，路由将避开它们"——**不声称"已自动改用其他候选成功"**，除非该判断有成功 attempt 证据；耗尽提示只陈述事实与去向链接。

【现状】对照：总览当前是四张键值表 + 两条横幅，无状态分型、无结论层、缺数据按 0/空串处理；本节为整体重设计。

## 7. 各主页面布局

### 7.1 通用规则

- 延续 `app-page` / `app-page-split` 骨架【现状】。
- 一级视图密度上限：结论卡 ≤1 组、行动横幅 ≤3 条、明细表 ≤1 张，超出进折叠或二级标签页。
- 页面标签页（模型来源/模型与路由/请求活动）用设计系统的分段控件 `oc-seg`，URL hash 同步，深链可达。

### 7.2 模型来源（Providers 重排）

```
┌──────────────┬──────────────────────────────────────────────┐
│ 模型来源  +  │  DeepSeek（就绪）                             │
```

## 8. 状态与反馈设计（全页统一）

### 8.1 加载

- 首次加载用骨架占位（表格行骨架/卡片块骨架），替换居中 spinner；纯前端。
- 后台刷新（SSE invalidate【现状】）不打断阅读，数据原地更新。

### 8.2 空态

三件套：发生了什么 → 为什么 → 去哪（真实链接按钮）。示例：

| 位置 | 文案 | 链接 |
|---|---|---|
| 模型测试无目标 | "没有可测试的目标。候选由模型来源的目录编译而来。" | 「去模型来源页」 |
| 请求列表为空 | "还没有请求记录。把 agent 接到网关后，这里会出现每一次模型选择。" | 「去接入向导」 |
| 用量分析无数据 | "账本从空开始。" | 无（如实，不给假按钮） |
| 模型入口候选池为空 | "该模型入口还没有候选，agent 调用它会失败。" | 「去候选高级页添加」 |

### 8.3 错误

统一格式：**人话结论（粗体）+ 技术原因（等宽小字）+ 建议动作**；request_id 与复制能力【现状】保留。

> 配额查询失败
> `HTTP 500 · request_id=…` · 服务可能在重启中
> [重试] [去诊断页]

### 8.4 未保存草稿

> **2026-11-23 更新**：配置保存已改为**自动保存 + 热加载**，见
> [design/config-autosave.zh.md](./design/config-autosave.zh.md)。本节描述的「校验 / 应用」
> 操作栏被保存状态栏取代（编辑 → 防抖 → apply → 运行时目录热替换，只有 `[server]` 变化才需重启）；
> 草稿 store 跨页共享、CAS 基准、冲突不静默覆盖、密钥只见引用等可靠性约束仍然有效。

【目标】配置草稿提升为**全局前端 store**（模型入口/候选/设置页共享同一草稿与统一应用栏），纯前端，无宿主依赖：

```
┌──────────────────────────────────────────────────────────┐
│ ● 有未保存的修改（3 处）  [校验]  [应用…]   放弃更改        │
│   应用后需重启网关生效。                                    │
└──────────────────────────────────────────────────────────┘
```

- **切页不再丢草稿**（全局 store 天然解决）；刷新/重启应用后的恢复：草稿暂存到本机存储，**草稿标识必须包含服务身份 + revision**——不能用 config digest 充当服务身份（digest 随配置变化，同一服务重启前后就不同），标识用服务的 base_url/data-dir 等稳定标识 + revision 组合；身份不匹配的过期草稿**隔离保存并提示"发现来自其他服务/旧配置的未保存草稿，可对比后决定恢复或丢弃"**，不静默丢弃。
- 暂存内容按配置的脱敏语义对待：草稿里的凭据是**引用**（`env:`/`file:`/`keyring:`）而非明文；**key 明文在管理面读取时不回传（API 只返回引用 + 指纹后 4 位），仅录入表单瞬时持有、不得持久化到任何存储**。
- **含用户内容的输入（模型测试的 prompt/历史）不进本机存储**——那是敏感输入，持久化属于需支持的宿主能力，未落地前应用关闭即丢，并如实告知。
- **每次编辑（含放弃更改、撤回单处修改）都使 validRevision 失效并要求重新校验**【现状已有失效逻辑，须保持完整：不只是"锁定后不能改"，而是"改了就重新校验"】——校验通过锁定 revision 后才可应用【现状 validRevision 机制保留】。

### 8.5 并发冲突（CAS 409）

【现状】apply 撞 CAS 只弹错误 toast。【目标】409 专用面板，**不提供静默强覆盖**：

> 配置已被其他会话修改
> 你打开配置后，revision 已从 `a1b2…` 变为 `c3d4…`。
> [载入最新配置并对比]（把双方改动并排列出：哪些是你改的、哪些是对方改的）
> [在新配置上重做我的修改]（逐项列出你的改动，确认后重新校验再应用）
> [放弃我的修改]

- "覆盖对方"选项不提供——CAS 的意义就是不覆盖；确要覆盖的用户走"载入最新→手动重改→重新应用"，每一步有审计。
- 对比/重做视图为前端 diff UI（纯前端，数据来自当前 GET config + 本地草稿）；首期可先只做"放弃 / 载入最新并保留我的改动清单（文本形式）"。

### 8.6 重启生效

【现状】apply 返回 `restart_required: true`（服务端不自我重启）；桌面壳已有 `supervisor_restart` 命令（退避重启），设置页已有独立"重启"按钮。

【目标】三级：

1. 【纯前端】"已应用未重启"期间全局持久横幅："配置已保存，重启后生效（当前运行 digest `a1b2…`）"；侧栏状态点转黄。
2. 【纯前端编排·仅 Tauri 桌面模式】「应用并重启」：串现有 apply + 现有 `supervisorRestart` 命令，等待 ready 后自动刷新；失败回退为横幅提示。**不是新壳能力**——两个调用都已存在，缺的只是编排与确认弹窗（明示"网关将中断数秒"）。**浏览器模式不可调用宿主命令**；**Tauri 连接外部服务模式时壳不托管该进程，重启属外部部署的职责**——两种模式下入口隐藏，改显示"配置已保存；请手动重启网关生效（或联系服务管理员）"。连接/断连状态仍按 supervisorStatus 真实呈现（显示"已连接外部服务"），只是不提供重启动作。
3. 热生效（不重启应用路由配置）**超出本文范围**，不作为目标或承诺。

| 对比结论行（最快首事件延迟/最快 TPS） | 纯前端 | 只比有数据的列 |
| **成本对比列** | **需支持** | 执行响应当前无成本字段，候选价格是否可从前端配置可靠读出需核对契约；落地前成本列显示"—"，不折算 |
| **逐 token 流式输出** | **需支持（API 增量）** | `playground/execute` 当前聚合返回；增量需新端点或 SSE 变体 |
| **取消** | **前端部分可做 + 需支持** | "停止等待"= 前端放弃等待并如实标注"已停止等待；上游请求可能继续并产生费用"——不冒充"已取消上游"；真正终止上游需 API 增量 + 契约定义语义 |
| 测试请求的记账口径 | 如实标注 | `virtual:` 目标走正常路由**会入账本**（标记 playground/Direct）；`candidate:` 目标绕过路由、不计路由决策；两者对用量统计的影响需按代码核对后在页内标注，不得笼统写"不计入统计" |

### 9.2 请求解释（请求详情重排）

【现状】键值表 + 事后静态时间线 + attempts 表 + 裸 JSON；`dispatch_source` 有真实枚举值（`sticky_previous`/`context_hold`/`strategy`/`failover`/`fallback` 等）。

【目标】三层：

```
第一层：结论卡（只陈述可证事实）
┌────────────────────────────────────────────────────────────┐
│ ✓ 成功 · 由 glm-5.3-flash 应答（312ms · 首事件 98ms）         │
│   派发来源：策略选择（strategy）                             │
│   成本 $0.0021（应答 $0.0019 + 路由 $0.0002）                │
│   [为什么是这个模型 ▾]  ← 展开显示生成该结论的账本原始字段       │
└────────────────────────────────────────────────────────────┘

第二层：路由时间线（默认展开；数据来自请求完成后的决策快照，页头注明）
  ● 选择    smart → glm-5.3-flash（档位 weak）      [依据 ▾]
  ● 策略    cascade：2 条贡献                       [逐条展开 ▾]
  ● 计划    glm-5.3-flash → deepseek-chat           [完整计划 ▾]
  ● 派发    glm-5.3-flash @ deepseek · 来源 strategy
  ● 接力    （无）
  ● 判官    （未启用）
  ● 结果    success · 0 次切换

第三层：技术详情（默认折叠，永不删除）
  attempts 全表 / contributions / preference / judge 原文 /
  request_id / session_key / branch_id / plan_id / reason_codes 原值 /
  config_digest（仅是指纹；当前没有按 digest 取回历史配置的端点）
```

硬规则：

- **reason 映射表白名单**：`reason_codes`/`dispatch_source` 只有映射表里有的才翻译成人话（如 `sticky_previous`→"沿用上一轮模型/上下文保持"（意图是提高 prompt 缓存命中可能，**实际缓存是否命中以上游实际行为与计费为准，界面不保证**）、`context_hold`→"沿用上一轮派发"）；映射表之外**显示原始码**，绝不编造因果叙述。
- **严禁编造"因为简单任务所以选弱档"这类因果**——策略内部判定没有以人类可读形式暴露，就只显示策略贡献原文。
- 质量评语只在判官启用且账本有 judge 数据时出现；没有就不写。
- 成本显示换算后的可读值；价格未配置的请求显示"未计价"；micros 原值在技术详情层。
- sticky/亲和只按 `dispatch_source` 真实值展示复用状态，不做"命中率"之类无来源的汇总。
- "进行中的请求"实时时间线**需支持**（SSE kinds 增量 + 事件契约）；落地前页头注明"本时间线来自请求完成后的快照回放"，不冒充实时。

### 10.1 分层

- 陈述句；错误消息永远带"现在怎么办"。

### 10.3 双语

【现状】i18n 字典已有。【目标】新文案先中文键、字典补英文；技术详情层保持英文原值。

## 11. 视觉层级方向

延续[设计系统](./dev/frontend-design-system.zh.md)全部既定决定，**不推翻**：UnoCSS + vendored OpenChamber 预设、Vercel 主题亮色默认（`vercel-light`/`vercel-dark`）、Inter 正文 + Geist Mono 等宽（内置 latin 子集）、lucide-react 图标统一走 `Icon` 注册表、类名完整字面量约定与 `check:uno` 门禁。

产品层追加方向：

1. **primary 与 selection 的语义严格执行**：primary 蓝 = "去做"（运行/应用模型选择/编译等主动作按钮）；侧栏与列表选中态用中性 selection 色，不用主色【设计系统已有此规则，落实到位即可】。状态色不做装饰——状态色只标记状态，primary/强调不与状态色混用。
2. **数字层级**：结论卡数字用一档放大的既定字号（如 `text-xl/2xl`），**不盲用巨字号**——数字多、精度高的页面（用量分析）保持表格节奏，只有首页结论卡放大。
3. **每页一个视觉重心**：结论卡或图表是重心，其余 muted 收紧；修正模型来源页五区等权堆叠。
4. **状态色纪律**：进行中=蓝、错误=红、注意=黄、正常=绿；配额条中性色 + 阈值变色，无装饰渐变；**断连/数据过期不是绿**（§6 状态 F）。
5. **时间线图形化**（纯前端）：竖向节点线（圆点+连线），失败红点、接力黄折返；数据来源不变。
6. 新组件一律语义 token，禁硬编码色值（`check:uno` 变量体检已有）。

## 13. 实施阶段与验收

每阶段独立可发布，不改 API 冻结语义；纯前端项不依赖任何"需支持"。

### Phase D1 草稿与反馈止血（纯前端）

- 配置草稿全局 store（模型入口/候选/设置共享）+ 应用栏；本机暂存（服务标识 + revision 校验，脱敏语义，过期草稿隔离可对比）；模型测试 prompt 不落本机存储。
- CAS 409 面板（放弃 / 载入最新并对比；不提供静默覆盖）。
- 空态补真实链接；账号启用开关；目录搜索与"已勾选"过滤。
- Playground 各列独立完成渲染 + "停止等待"（如实标注）+ 运行中超时提示。
- **验收**：改配置切页/跨页编辑不丢；两窗口并发改配置各自得到可理解出路且无一键覆盖；模型测试运行中先完成的列先出现；空态每条有可点链接或如实说明。

### Phase D2 信息架构重组（纯前端）

- 导航收敛为 7 + 系统区；`/quotas`→模型来源标签页、`/models`→高级标签页、`/logs`→请求活动标签页（旧 path 直达对应标签）。
- 首页七态渲染（成本卡=已计价金额/覆盖未知，"未知≠0"、断连不显绿、更新中横幅）；入口健康聚合【需支持】未落地前健康卡只显示熔断/候选健康摘要。
- 模型来源主-从两栏 + 标签页（余额二级：厂商 usage 接口的余额/计划/键限额；无接口厂商明确标注）；模型与路由主页 + 高级二级；编译已自动化，「重新编译候选」仅作失败重试。
- 术语一层替换（§10.1），micros→$ 显示。
- **验收**：新用户不看文档能说出"去哪加 key、去哪建模型入口"；旧路由全部可达且落到正确标签；`check:uno`/lint/现有测试全绿。

### Phase D3 解释与对比（前端为主）

- 请求详情三层重排：结论卡（reason 映射白名单 + 溯源展开）+ 图形时间线 + 技术详情；无映射 reason 显示原值。
- Playground 目标分组选择 + 默认单目标 + 对比结论行（有数据列）。
- 【需支持】Playground 成本对比列（契约核对/DTO 增量后）。
- 【需支持·API 增量】逐 token 流式输出；真正终止上游的取消语义。
- **验收**：任一结论展开可见生成它的原始字段；判官未启用无质量评语；未计价成本显示"—"；"停止等待"文案如实；无编造因果。

### Phase D4 打磨与可访问性

- 骨架加载、后台刷新不打断、键盘导航 + 焦点可见补齐、AA 对比度审计、`<html lang>`。
- 「应用并重启」编排（现有 apply + 现有 supervisorRestart，纯前端，**仅 Tauri 桌面模式**；浏览器/外部服务模式不提供，见 §8.6）+ 全局"已应用未重启"横幅。
- 【需支持·API 增量】进行中请求的实时路由事件流 → 实时时间线。
- 【需支持·API 增量】按 digest 取回历史配置（当前只有指纹无取回端点）；落地前技术详情层如实写"仅指纹"。
- **验收**：全键盘完成 J1–J5；AA 审计通过；应用并重启失败回退为横幅而非卡死；断连期间界面无误导性绿色状态；浏览器模式下不出现任何"应用并重启"入口。
